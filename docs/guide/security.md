# 账号安全与加密机制

子虚亭采用客户端加密模型：账号密钥在你的设备上生成，密码解锁后可将工作台电脑授权、即时消息与附件同步到其他设备；云端服务仅保存密文和必要的路由/业务元数据，不掌握账号根密钥或明文消息内容。

工作台对电脑的远程控制继续通过设备级 Noise 加密通道完成，桌面 Agent 仍在你自己的电脑上运行，账号同步不会将桌面执行权迁移至云端。

## 账号解锁与登录保护

### 1. 密码与 256 位恢复码

- 注册账号时，客户端在本地生成随机 256 位账号根密钥，并分别用你的密码和随机生成的 **256 位恢复码** 包装保护。
- 原始密码不会直接提交给服务器：客户端使用 PBKDF2-HMAC-SHA-256（600,000 次迭代，随机 32 字节盐）派生登录证明与密钥包装材料，服务端再对登录证明做带盐 scrypt 校验。
- 恢复码不会以明文上传服务器，请务必在注册完成时妥善离线保存。
- 修改密码会保留账号根密钥和历史数据，仅轮换包装层并撤销其他已登录会话。忘记密码时，可使用 `UID/用户名 + 恢复码` 恢复账号并重设密码与新恢复码（原恢复码、动态码种子与通行密钥随之失效）。

### 2. 默认动态码（TOTP）与外部验证器

- 账号默认启用标准 RFC 6238 TOTP 动态码（HMAC-SHA1，6 位数字，30 秒周期）。新密码登录在通过动态码验证前不会获得完整会话或解密密钥包。
- 已登录设备可在「我的 → 登录与安全 → 登录动态码」直接查看内置动态码，切入后台或离开页面会自动隐藏并停止刷新。
- 首次注册或通过恢复码重置密码后，可在短时有效窗口内通过标准 `otpauth://totp` 二维码或 Base32 密钥将动态码导入 Google Authenticator、Microsoft Authenticator 等外部验证器；跳过外部验证器不会关闭内置动态码保护。
- 已授权的纯 Rust 桌面适配器也支持通过**离线秘钥簿**在本机安全缓存动态码与恢复码，详见 [桌面适配器安装与配置](desktop-adapter.md#离线秘钥簿)。

### 3. 跨设备扫码登录与通行密钥

- **双向扫码登录**：既可由新设备扫描已登录设备展示的登录二维码，也可由新设备出示本机登录码、已登录设备扫码核对短代码后批准。已登录设备使用新设备的临时公钥加密封装账号根密钥，交由服务端一次性中转完成交接。
- **通行密钥（WebAuthn）**：可在「登录与安全 → 可信设备」登记通行密钥，用于敏感凭据导出与设备管理操作；移除通行密钥会撤销其他登录会话。

## 云端与客户端的数据边界

| 数据类别 | 云端保存形态 | 谁可以解密 |
| --- | --- | --- |
| 账号私钥包、工作台配对身份与路由票据 | AES-256-GCM 密文 | 账号拥有者的已解锁客户端 |
| 即时消息正文、提问/授权卡片内容与回复 | 签名加密信封 | 发送时列入接收方的会话成员 |
| 聊天附件原文、文件名与 MIME 类型 | 文件密文 + 加密描述 | 获得该文件密钥的会话成员 |
| 用户名、公开昵称/头像、联系人/群成员关系、消息序号/时间/密文大小 | 业务元数据 | 服务端可见 |

- **客户端搜索与聊天导出**：聊天内容搜索与 Markdown / JSON 导出均在客户端解密后本地执行，搜索关键词与明文内容不发送给服务器。
- **云端 7 天自动过期与本地持久化**：云端加密消息密文与聊天附件密文最多保留 7 天，过期后由服务端自动清理（头像与表情包长期保留）；客户端 IndexedDB 本地加密缓存不受云端过期删除影响。
- **独立零知识管理台**：站点运维管理台（`src/admin`）部署在独立站点或路径，仅展示聚合指标与业务元数据（从不接触任何 E2EE 私钥或明文聊天内容），支持由主站扫码或同浏览器一键核对码签发隔离的管理会话。
- **工作台附件**：优先经设备级 WebRTC 直连传输；启用对象存储回退时，对象存储仅接收带随机对象名的 AES-256-GCM 密文块，不接收原始文件名和解密密钥。

## 加密协议要点

- **账号与私有配置**：随机 256 位账号根密钥经 HKDF 派生子密钥，使用绑定账号与记录 ID 的 AES-256-GCM AAD 加密私有配置与工作台配对记录。
- **端到端消息**：每条消息使用新生成的 P-256 ECDH 临时密钥与随机 AES-256-GCM 内容密钥，分别为当前会话成员包装内容密钥；账号 ECDSA P-256 签名覆盖上下文、接收方列表与全部密文。
- **交互授权防篡改**：授权卡片的回复独立签名并绑定会话、消息与交互 ID，服务端无法单方面伪造有效的授权通过状态。
- **联系人公钥固定**：客户端会固定首次获取的联系人公钥并加密同步；聊天顶部提供安全码用于线下核对，公钥异常变更不会静默接受。
- **群聊成员边界**：群消息逐条向当前成员包装密钥；移出群的成员无法解密后续新消息，新加入成员无法自动解密入群前的历史消息。

## 信任边界与已知局限

请在使用与部署时清楚了解当前安全模型的边界：

- **非独立审计协议**：本方案基于标准 [W3C Web Cryptography API](https://www.w3.org/TR/webcrypto/) 原语构建，**并非** Signal、Matrix 或 MLS 协议实现，且尚未经过第三方独立密码学审计。
- **无双棘轮前向保密**：不提供双棘轮（Double Ratchet）级别的前向保密或入侵后自愈能力——如果账号私钥泄露，攻击者可能解密其获取到的历史密文。
- **客户端与发布链可信**：浏览器、操作系统、Agent 运行环境以及静态前端发布链位于信任边界内。自托管或高安全需求场景可启用 [前端发布验签](../deploy/frontend-verification.md) 以降低前端篡改风险。
- **撤销限制**：撤销设备授权或退出登录会阻断后续访问并关闭通道，但无法远程收回已经被对方或攻击者下载到本地的明文与密钥。
- **密码强度**：请使用密码管理器生成高强度密码，避免弱密码遭受离线暴力破解。
